What is an Agent Loop?

Core execution cycle enabling LLMs to solve tasks autonomously:

┌─────────────────────────────────────────────────────┐ │ AGENT LOOP │ │ │ │ Input → LLM → Tool Calls? → Execute Tools │ │ ↑ ↓ │ │ └─────────── New Context ─────────────────────┘ │ │ │ Repeat until task is complete or stop condition │ └─────────────────────────────────────────────────────┘

Key characteristics:

  • LLM generates responses with potential tool calls
  • Tools execute external actions (read files, run commands, API calls)
  • Tool results feed back into context for next LLM turn
  • Loop continues until LLM decides task is done

Pi Monorepo Context

Pi is a monorepo with 5 core packages:

packages/
├── ai           # Multi-provider LLM API (OpenAI, Anthropic, Google, etc.)
├── agent        # Agent runtime (this is where the loop lives)
├── coding-agent # Interactive CLI (orchestrates agent runtime)
├── tui          # Terminal UI for interactive mode
└── web-ui       # Web components for chat interfaces

Agent loop implementation:

  • Core file: packages/agent/src/agent-loop.ts
  • Types: packages/agent/src/types.ts
  • Entry points: agentLoop() and agentLoopContinue()

Pi's Agent Loop Architecture

Key design decisions in runLoop():

  • Two-level loop structure:
    • Outer loop: Handles follow-up user messages mid-execution
    • Inner loop: Processes tool calls and steering messages per turn
  • Event-driven: Emits events throughout execution for UI/monitoring
  • Context management: Maintains message history, system prompt, tools
  • Streaming-first: LLM responses streamed token-by-token

Events allow TUI/web-ui to update in real-time without polling

Key Components: AgentContext

The AgentContext maintains state across turns:

interface AgentContext {
  // Message history (all roles: user, assistant, toolResult)
  messages: AgentMessage[];
  
  // System prompt passed to LLM
  systemPrompt: string;
  
  // Available tools for the agent
  tools: AgentTool[];
}

Important: Messages are stored as AgentMessage types internally, converted to LLM-specific Message types only at API boundary.

Key Components: AgentEvent

Events emitted during loop execution (partial list):

Agent Lifecycle: agent_start → agent_end Turn Lifecycle: turn_start → turn_end Message Events: message_start → message_update → message_end Tool Events: tool_execution_start → tool_execution_update → tool_execution_end

Event sink: (event: AgentEvent) => Promise<void> | void

TUI and web-ui subscribe to these events to render UI

The Two-Level Loop Structure

Simplified from runLoop() in agent-loop.ts:

// Outer loop: handle follow-up messages
while (true) {
  let hasMoreToolCalls = true;
  
  // Inner loop: process tool calls per turn
  while (hasMoreToolCalls || pendingMessages.length > 0) {
    // 1. Process any pending steering messages
    // 2. Stream assistant response from LLM
    // 3. If tool calls: execute them (parallel/sequential)
    // 4. Add tool results to context
    // 5. Check stop conditions
  }
  
  // Check for follow-up user messages
  const followUp = getFollowUpMessages();
  if (followUp.length > 0) { pendingMessages = followUp; continue; }
  break; // No more work, exit loop
}

Context Flow Per Turn

1. Start turn: Emit turn_start event ↓ 2. Apply context transform (optional hook) ↓ 3. Convert AgentMessage[] → LLM-compatible Message[] ↓ 4. Stream LLM response (emit text/tool call events) ↓ 5. If tool calls exist: a. Execute tools (parallel or sequential) b. Emit tool execution events c. Add tool results to context ↓ 6. Emit turn_end event ↓ 7. Loop back to step 1 if more tool calls

Tool Execution Modes

Pi supports two execution modes:

  • Parallel (default): Execute all tool calls concurrently
  • Sequential: Execute tool calls one by one

Triggers for sequential mode:

  • Global config: toolExecution: "sequential"
  • Per-tool: tool.executionMode === "sequential"

Tool execution pipeline:

prepareToolCall → validateArgs → executeTool → afterToolCall hook → finalize

Streaming & Real-time Updates

LLM responses are streamed token-by-token via streamSimple() from packages/ai:

  • Text: text_start → text_delta → text_end
  • Thinking: thinking_start → thinking_delta → thinking_end
  • Tool calls: toolcall_start → toolcall_delta → toolcall_end

Partial messages updated in context as stream progresses:

for await (const event of response) {
  switch (event.type) {
    case "text_delta":
      partialMessage = event.partial;
      context.messages[lastIndex] = partialMessage;
      emit({ type: "message_update", ... });
  }
}

Stop Conditions

The loop stops when any of these conditions are met:

  • LLM response has stopReason: "error" or "aborted"
  • No tool calls in LLM response
  • All tool calls have terminate: true
  • shouldStopAfterTurn config hook returns true
  • User sends interrupt signal (Ctrl+C)

Follow-up messages: If user sends new messages while agent is running, they're queued and processed in next outer loop iteration.
