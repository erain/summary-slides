The problem — 1/2

AI Workers Are a Weird New Workload

An “agent” here just means a program that calls an AI model repeatedly to do multi-step work: write code, run tests, retry, look things up. That shape breaks the two molds platforms were built for:

Not a web service

A web server is stateless and interchangeable. An agent accumulates state — half-edited files, downloaded tools, a memory of what it tried. Kill it carelessly and the work evaporates.

Not a batch job

A batch job runs to completion and exits. An agent lingers: it waits on model answers, wanders down blind alleys, and can spend real money in a loop if nobody watches it.

So the platform must do four things

  • Isolate — untrusted, machine-written code runs in a locked box, with CPU/memory caps.
  • Pre-wire — every worker should start with its code, tools, and keys already in place.
  • Pause and resume — shelve an idle worker and wake it later, files intact.
  • Inspect — open the box and look over the worker’s shoulder while it runs.

The answer in two layers — 2/2

Two Layers: the Form and the Fleet

Think of eating at a restaurant. AX is the order ticket — what you want, written down. Agent Substrate is the kitchen — the stoves, chefs, and pantry that actually cook it.

Why two layers? Storing millions of short-lived tickets inside Kubernetes itself would choke its database (etcd: single-digit GB, write bottlenecks). So AX keeps its ticket list in Redis and rents locked boxes from Substrate. Sources: DESIGN.md:5, README.md:13, deploy/ax-server.yaml.

What you declare — 3/4

You Fill In Three Forms

Everything is one YAML file with up to three documents. Plain reading of each:

Form (real name)Plain meaningExample from examples/task.yaml

WorkspaceThe starting kit, packed once, reused everywhere. Code to clone, tool servers to call, skill files, instructions.default-workspace: clone chalk/chalk.git, reach the git-tools tool server, load nodejs skills.

Plus a shared folder label: an atespace (say default) is just a namespace so teams don’t collide — like a kitchen zone. Sources: docs/concepts.md, docs/manifests.md, examples/task.yaml.

What happens when you hit enter — 4/6

ax apply: From Ticket to Locked Box (1–3)

ax apply -f task.yaml   # file your three forms
ax watch task task123   # watch the status line change
ax ssh task123 -- ls /workspace   # peek inside the box
  1. Desk checks the ticket. ax-server validates names (lowercase, ≤63 chars — they become Substrate names), fills in the atespace default, saves a copy in Redis, and takes a per-task lock so two edits can’t collide. server.go, types.go.
  2. Desk reserves a kitchen zone. The reconciler calls EnsureAtespace(default) — create it if missing, shrug if it exists. reconciler.go: Reconcile.
  3. Desk picks a recipe card. It builds an ActorTemplate named like task123-tmpl-a1b2c3d4 — the short hash covers the container image plus environment, so any spec change mints a new card and old revisions sit side by side. The card always says: start /usr/local/bin/ax-task-runner, mount a durable folder at /workspace, answer health checks on port 80. substrate/client.go: BuildActorTemplate; reconciler.go: taskTemplateName.

What happens when you hit enter — 5/6

Ticket to Locked Box, continued (4–6)

  1. Kitchen assigns a box, named after your ticket. EnsureActor(default, task123) creates one box per task — actor name always equals task name, which is also how network requests find it later. Already exists? Reuse it. Crashed? Roll it back to its last good snapshot. Half-deleted? Wait and retry. substrate/client.go: EnsureActor.
  2. The box phones home when its kit is packed. AX polls GET /readyz on the box (up to ~15 s): 503 = still cloning code, 200 = ready. Then it flips two flags you can watch: WorkspaceReady (kit packed, stays true) and Ready (kit packed AND running — the one to wait on). reconciler.go: waitForWorkspaceReady; metadata/server.go.
  3. You watch and visit. ax watch streams those flag changes; ax ssh (needs debug: true) runs commands inside the box via the router. Deleting the ticket deletes the box first, then its recipe cards, and only then removes the record — ax delete waits for all of it. reconciler.go: ReconcileDelete; docs/networking.md.

The one-line version

Ticket in → zone reserved → recipe card picked → locked box opened → kit packed → flags flip → you peek in. Every later feature (pause, resume, delete) is a variation on this path.

Inside the locked box — 6/8

Morning Routine of a Locked Box

The box never runs your command directly. Its manager (ax-task-runner, process #1) follows the same morning routine every boot. runner/runner.go: Run; docs/sandbox.md.

1. Wake up & open the desk

Read the ticket from AX_TASK_YAML and the kits from AX_WORKSPACES_YAML. Open a small info desk on port 80: /healthz (alive?), /readyz (kit packed?), /metadata/.../task (what am I?).

2. Pack the kit — first morning only

In binding order: clone each Git repo, lay out skill files, write tool-server addresses, and if the binding carries a plain-words goal (“install deps, run tests”), hand it to a helper agent (up to 10 min). Stamp a marker file under /ax so tomorrow’s boot skips the packing.

3. Start the day’s work, supervised

Launch spec.command as a supervised child in the first kit’s folder, with AX_METADATA_URL plus your env vars. If the worker finishes, the manager stays awake so you can still inspect the box.

Why directors should care

First boot is slow, second boot is fast (packing skipped). The marker files are the whole trick — lose them and every resume re-clones and wipes state. Custom images must keep the same routine: /usr/local/bin/ax-task-runner, port 80, pack-once, supervise. docs/runner.md checklist.

Pause, wake, and peek — 7/8

Pause It, Wake It, Peek Inside

Shelve it: ax suspend

Kitchen photographs the /workspace folder into a snapshot bucket, frees the stove (CPU/RAM), and marks the ticket Suspended with Ready=False (TaskSuspended). You stop paying for an idle box but keep everything it made.

Wake it: ax resume

Kitchen seats a fresh box at a free stove and unpacks the photo. Same files, brand-new processes — that’s why packing is skipped and the manager restarts the command. Status flips back to Running. substrate/client.go: SuspendActor/ResumeActor.

Peek inside: one receptionist for every box

Boxes get no private address. Every request goes to one receptionist — the atenet-router — carrying a name tag: header ate-target-actor: default/task123. The receptionist finds the stove, wakes the box first if it was shelved, and forwards the call. ax ssh is just “run this command” sent through the receptionist to helper services inside the box — which is why it only works when the ticket says debug: true. docs/networking.md; guest/client.go: DialTarget.

curl -H "ate-target-actor: default/task123" http://atenet-router.ate-system/readyz

Honest tradeoffs — 8/9

What This Buys You, and What It Costs

DecisionWhat you gain (plain)What you pay (plain)
Tickets in Redis, not KubernetesMillions of short-lived tasks without choking the cluster database.Second source of truth to back up, secure, and keep consistent with the kitchen.
One box per ticket, strong walls (gVisor)Machine-written code can’t snoop on neighbors; CPU/RAM caps hold.More boxes = more overhead than threads in one process. Density depends on pausing the idle.
Pack the kit once, stamp a markerFast resumes; reproducible starting kits across teams.First boot is slow (clones + up-to-10-min helper agent); a lost marker means lost work.
SSH-style peeking off by defaultNo silent backdoor into every box; you opt in per ticket.Debugging a non-debug box means redeploying it.
Passwords in Kubernetes secrets, referenced by nameRotate a key with one apply; it never sits in the ticket file.Someone must still guard those secrets and their access list. (ax-server needs get/list/watch.)

Where the roadmap admits weakness: setup and running share one box today (setup keys can see runtime); idle detection is manual (suspend); no per-task identity or spending guardrails yet. docs/roadmap.md: actor split, least privilege, auto-suspend, SPIFFE, budgets, telemetry.

Takeaways — 9/9

Takeaways for Your Next Design Review

  1. Say “ticket and kitchen,” not “orchestrator and substrate.” AX files and tracks the request; Substrate supplies the locked box, the stove, and the pantry. The seam is the actor name = task name.
  2. Budget for two clocks: slow first boot (kit packing) vs. fast resume (snapshot unpack). Size timeouts and UX around that gap.
  3. Treat pause as your cost lever: every idle-but-running box burns a stove. Suspend aggressively until auto-suspend lands.
  4. Default-deny peeking: leave debug off in production; enable it only where a human is actively watching.
  5. Remember what’s missing: no spending caps, no per-box ID cards (SPIFFE), no automatic audit trail yet — plan compensating controls. AX is pre-release; pin the commit you evaluated.
